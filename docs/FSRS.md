# FSRS — сонголтоор хэрэглэх давтлагын алгоритм (Phase 3)

Огноо: 2026-11-12. SM-2 нь анхдагч хэвээр; FSRS-ийг хэрэглэгч **Тохиргоо → Давтлагын алгоритм** хэсгээс сонгоно. Хуучин карт, түүх, синк, экспорт бүгд хэвээр ажиллана.

## 1. Яагаад SM-2-ыг орхихгүй вэ?

SM-2 нь 1987 оны алгоритм бөгөөд хэрэглэгчийн санах чадварыг загварчлахгүй, зөвхөн `ease` коэффициентээр интервалыг үржүүлдэг. FSRS нь DSR (Difficulty, Stability, Retrievability) загвараар «мартах муруй»-г тооцдог тул ижил ачаалалд цөөн давтлага шаарддаг. Гэхдээ:

- одоо байгаа 100,000 картын индекс, queue, түүх, синк бүгд SM-2-ийн `repetitions/interval/ease/dueOn` талбарт тулгуурладаг;
- FSRS-ийг албадан сольсноор хуучин түүх утгагүй болж, хэрэглэгчийн хуваарь гэнэт өөрчлөгдөнө.

Тиймээс FSRS нь **сонголт** бөгөөд ижил `ReviewSchedule` бүтцийг буцаадаг. Нэмэлт талбарууд (`algorithm`, `stability`, `difficulty`, `lastReview`) зөвхөн FSRS-ээр хуваарьлагдсан картад байна.

## 2. Хэрэгжүүлэлт

`lib/knowledge/fsrs.ts` — FSRS-4.5, 17 параметр, нийтлэг анхдагч жин:

```text
0.4872, 1.4003, 3.7145, 13.8206, 5.1618, 1.2298, 0.8975, 0.031, 1.6474,
0.1367, 1.0461, 2.1072, 0.0793, 0.3246, 1.587, 0.2272, 2.8755
```

- Мартах муруй: `R(t,S) = (1 + 19/81 · t/S)^(-0.5)`, `R(S,S) = 0.9`.
- Интервал: `I(r,S) = S/(19/81) · (r^(1/-0.5) − 1)`, `r = 0.9` үед `I = S`.
- Анхны тогтвортой байдал `S0(G) = w[G−1]`, анхны хүндрэл `D0(G) = w4 − e^(w5·(G−1)) + 1`, `D ∈ [1,10]`.
- Амжилттай давтлагад `S' = S·(e^w8·(11−D)·S^(−w9)·(e^(w10·(1−R))−1)·w15(хэрэв G=2)·w16(хэрэв G=4) + 1)`, амжилтгүйд `S' = w11·D^(−w12)·((S+1)^w13 − 1)·e^(w14·(1−R))`.
- Хүндрэл: `ΔD = −w6·(G−3)`, `D' = D + ΔD·(10−D)/9`, дараа нь `D0(3)` руу буцаах дундажлал (`w7`).

**Үнэлгээний буулгалт.** Апп 0–5 үнэлгээтэй (SM-2). FSRS дөрвөн үнэлгээтэй тул: `0–2 → Again`, `3 → Hard`, `4 → Good`, `5 → Easy`. Энэ нь «4-өөс доош үнэлсэн карт энэ давтлага дотор дахин гарна» гэсэн одоогийн зан төлөвийг хадгална.

**Хязгаарууд.** Амжилттай давтлагад тогтвортой байдал буурахгүй (`S' ≥ S`), алдааны дараа `0.01 ≤ S' ≤ S`, интервал `1…36500` хоног, коэффициент `0.5…2`. FSRS-4.5 нь нэг өдрийн доторх давтлагыг тусгайлан загварчлахгүй тул SM-2-ийн «нэг суралцах өдрийн дотор олон өдрийн шат руу үсрэхгүй» дүрэм хэвээр (өдрийн эхний давтлагын `before`-ыг ашиглана).

## 3. Түүхээс сурах

`lib/knowledge/calibrate.ts` — бүрэн FSRS сургалт (17+ жин, мянган давтлага, градиент) биш, **нэг параметрийн калибровк**:

1. Нэг картын дараалсан хоёр давтлагаас нэг ажиглалт гаргана: `(өнгөрсөн хоног, амжилт/алдаа, өмнөх интервал)`.
2. SM-2-ийн интервалыг 90% хадгалалтын тогтвортой байдлын ойролцоо утга гэж үзнэ.
3. `0.5…2.0` хооронд 0.05 алхмаар тогтвортой байдлын коэффициент хайж, ажиглагдсан үр дүнг хамгийн сайн тайлбарлахыг сонгоно (log-loss).
4. 40-өөс доош ажиглалттай бол юу ч өөрчлөхгүй; сайжруулалт нэг ажиглалтад 0.005-аас бага бол мөн анхдагчаа үлдээнэ.

Үр дүн нь `settings.extras.fsrsScale`-д хадгалагдаж, зөвхөн FSRS-ийн интервалыг үржүүлнэ. Түүх, карт, SM-2-ийн `ease` хөндөгдөхгүй. Хэрэглэгч «Түүхээс тохируулах» дарахад л ажиллана — автоматаар биш.

## 4. Шалгалт

`tests/fsrs.test.ts` — 19 тест:

- муруй `R(S,S)=0.9`, `I(0.9,S)=S`, цаг хугацааны бууралт, 0–1 хязгаар;
- үнэлгээний буулгалт, анхны `S0/D0`, хүндрэлийн өсөлт/бууралт, амжилт/алдааны тогтвортой байдал;
- `elapsedDays` (lastReview ба dueOn-оос), детерминизм, буруу үнэлгээний татгалзал;
- калибровк: өдрийн доторх давтлагыг алгасах, 40-өөс доош түүхэд өөрчлөхгүй, таамаглалтай нийцсэн түүхэд анхдагч хэвээр, илүү мартах → коэффициент буурах, илүү санах → өсөх;
- интеграци: SM-2 анхдагч хэвээр, FSRS сонгоход карт ба түүхэд төлөв хадгалагдах, дараагийн давтлагад интервал өсөх, коэффициент нөлөөлөх, `migrate()` round-trip.

## 5. Хязгаар ба дараагийн алхам

- FSRS-4.5-ийн 17 жингийн зөвхөн нэг хослолыг (тогтвортой байдлын коэффициент) түүхээс сурдаг. Бүрэн жин сургах нь сервер талын ажил (мянган давтлага, оптимизатор) — Phase 3-ийн дараагийн боломж.
- FSRS-5/6-ийн нэмэлт (нэг өдрийн доторх тогтвортой байдал, суралцах алхам) ороогүй.
- Бодит хэрэглэгчийн түүхээр коэффициент буруу тийшээ хазайх эрсдэлийг 40 ажиглалт + 0.005 gain босгоор хязгаарласан; илүү урт түүхээр дахин шалгах нь зүйтэй.
- Anki импорт/экспорт, PDF/текстээс карт үүсгэх нь Phase 3-ийн үлдсэн зүйл (`docs/IMPORT-EXPORT.md`).

## 6. Техникийн загвар (ADR)

### 6.1 Шийдвэр

SM-2-ыг **орлуулахгүй**, хажууд нь FSRS-4.5-ыг `settings.extras.srsAlgorithm` сонголтоор асаана. Шалтгаан: `ReviewSchedule` бүтэц, 100,000 картын индекс, queue, түүх, үүлэн синк, JSON нөөц бүгд SM-2-ийн дөрвөн талбарт тулгуурладаг; шууд солих нь хуучин түүхийг утгагүй болгож, хэрэглэгчийн хуваарийг гэнэт өөрчилнө. Хожим FSRS-3/5/6 руу шилжихэд зөвхөн `fsrs.ts` солигдоно.

### 6.2 Өгөгдлийн загвар

```ts
interface ReviewSchedule {
  repetitions: number; // хоёр алгоритмд ижил утгатай
  interval: number; // хоног
  ease: number; // SM-2-ийн хялбаршил (FSRS-д хэрэглэгдэхгүй, гэхдээ хадгална)
  dueOn: string; // YYYY-MM-DD
  algorithm?: "sm2" | "fsrs";
  stability?: number; // хоног, 0.01…36500
  difficulty?: number; // 1…10
  lastReview?: string; // YYYY-MM-DD
}
```

Талбарууд нь **optional** — хуучин карт, SM-2-ийн түүх, гадаад экспортод ямар ч өөрчлөлт шаардахгүй. `lib/knowledge/validation.ts` нь байгаа утгыг шалгаж, байхгүй бол хаяна; `lib/migration/migrate.ts` эдгээрийг `extras` шиг хаяхгүй тул `migrate()` round-trip тестээр баталсан. Синк нь `knowledge` мөрийг бүтнээр нь jsonb болгон дамжуулдаг тул серверт схемийн өөрчлөлт шаардлагагүй.

### 6.3 Инвариантууд

1. `dueOn = shiftDate(өнөөдөр, interval)` — queue зөвхөн `dueOn` ба `repetitions/interval`-аас хамаарна.
2. Амжилттай давтлагад `S' ≥ S`, алдаанд `0.01 ≤ S' ≤ S`; `D ∈ [1,10]`; `interval ∈ [1,36500]`.
3. Коэффициент `0.5…2` хооронд хязгаарлагдана (тохиргоо гэмтсэн ч интервал дэлбэрэхгүй).
4. Нэг суралцах өдрийн доторх давтлага нь өдрийн эхний `before`-ыг ашиглана (SM-2-ийн дүрэм хэвээр).
5. SM-2 → FSRS шилжихэд эхний FSRS давтлага нь SM-2-ийн `interval`-ыг «90% хадгалалтын тогтвортой байдал» гэж үзнэ; FSRS → SM-2 буцаахад `ease` хэвээр үлдэж, санах төлөв зөвхөн түүхэнд хадгалагдана.

### 6.4 Модулийн хил

| Модуль                                    | Хариуцлага                                                    | Гадаад хамаарал                   |
| ----------------------------------------- | ------------------------------------------------------------- | --------------------------------- |
| `lib/knowledge/fsrs.ts`                   | Цэвэр функцууд: муруй, интервал, `S0/D0`, шинэчлэлт           | байхгүй (зөвхөн `shiftDate`)      |
| `lib/knowledge/calibrate.ts`              | Түүхээс нэг коэффициент сурах                                 | `fsrs.ts`                         |
| `lib/knowledge/index.ts`                  | Queue: `due → relearning → fresh`, өдрийн шинэ картын хязгаар | `studyDate`, `dayBoundary`        |
| `lib/knowledge/session.ts`                | Сессийн хэмжээ, багц шүүлт, цаг                               | `index.ts`                        |
| `lib/knowledge/actions.ts`                | `reviewCard`: алгоритм сонгох, түүх бичих                     | `fsrs.ts`, `spaced-repetition.ts` |
| `components/settings/review-settings.tsx` | Сонголт, коэффициент, хязгаарууд                              | Store, actions                    |

Цэвэр функцууд нь цаг/сан/React-оос хамааралгүй тул тест хурдан бөгөөд синк, сервергүйгээр шалгагдана.

### 6.5 Алдааны горимууд

| Нөхцөл                                         | Зан төлөв                                                                                  |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `stability` эсвэл `difficulty` байхгүй/0/сөрөг | FSRS-ийн анхны утгаар дахин эхэлнэ; карт устахгүй                                          |
| `lastReview` ирээдүйд (цаг буруу)              | `elapsedDays` 0 болж, интервал буурахгүй                                                   |
| `interval` 0 боловч FSRS төлөвтэй              | `dueOn`-оос өнгөрсөн хоногоор тооцно (хуучин SM-2 бичлэг)                                  |
| Коэффициент гэмтсэн (`NaN`, string)            | 1 гэж үзнэ; UI 0.5–2 руу clamp хийнэ                                                       |
| Синкээр холимог алгоритмтай картууд ирэх       | Карт бүр өөрийн төлөвөөрөө үргэлжилнэ; глобал тохиргоо зөвхөн дараагийн давтлагад нөлөөлнө |
| `migrate()` үл мэдэгдэх талбар                 | Хадгална (extras биш), round-trip тестээр хамгаалав                                        |

### 6.6 Өөр хувилбарууд ба татгалзсан шалтгаан

- **FSRS-5/6 шууд:** нэг өдрийн доторх тогтвортой байдал, суралцах алхмыг загварчилдаг ч 4.5-аас илүү төвөгтэй, баримтжуулалт бага; Phase 3-д 4.5-ыг сонгож, шилжих замыг нээлттэй үлдээв.
- **Бүрэн 17-жин сургалт:** мянган давтлага, сервер талын оптимизатор, хувилбар тус бүрийн жин хадгалах шаардлагатай; хэрэглэгчийн дийлэнх нь 40–200 давтлагатай тул хэтэрхий эрт.
- **Anki-ийн FSRS-ийг импортлох:** Anki-ийн `.apkg`/SQLite-ээс жин, төлөв гаргах нь салангид ажил; одоогоор текст импорт л бий.
- **Багц бүрийн алгоритм:** сонголт нь хэрэглэгчийн түвшинд байх нь ойлгомжтой, гэхдээ багц бүрд тохиргоо нэмэх нь UI ба синкийн нарийн төвөгтэй байдлыг өсгөнө.

### 6.7 Нэвтрүүлэлт ба буцаалт

1. Тохиргоогүй хэрэглэгч бүр SM-2-оор үргэлжилнэ (анхдагч).
2. FSRS асаахад одоогийн `dueOn` хэвээр; зөвхөн дараагийн давтлагын интервал FSRS-ээр бодогдоно.
3. Буцаах: `srsAlgorithm`-ыг `sm2` болгоход дараагийн давтлага SM-2-ийн `ease`-ээр үргэлжилнэ; FSRS-ийн `stability/difficulty` карт дээр үлдэх боловч SM-2-ийн үр дүн тэдгээрийг дарж бичнэ.
4. Калибровкыг зөвхөн хэрэглэгч товч дарж хийнэ; автомат сургалтгүй тул гэнэтийн өөрчлөлт гарахгүй.
