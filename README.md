# Тогтмол v3 — Personal Study OS

**Нэг өдөр. Нэг жижиг алхам.**

v2-ийн хичээл, суралцсан өдрийн тэмдэглэгээ, хугацаа, тэмдэглэл, зорилго, амжилт, ажиллаж буй timer-ийг хадгалж, Next.js / TypeScript төсөл болгож хөгжүүлсэн хувилбар.

## Шууд ажиллуулах

Node.js **24** болон npm суулгасан орчинд:

```bash
git clone https://github.com/AriukagiinTuvshoo/TOGTMOL.git
cd TOGTMOL
```

```bash
npm ci
npm run dev
```

Браузераар `http://localhost:3000` нээнэ. Эхлээд **Хичээлүүд → Хичээл нэмэх**, дараа нь **Start study**.

Supabase тохируулахгүйгээр хичээл, timer, календарь, тайлан, зорилго, төлөвлөгөө болон JSON нөөц ажиллана. Энэ нь Next.js төсөл тул HTML файл шиг давхар дарж нээхгүй. Өмнөх дан HTML хувилбар `legacy/togtmol-v2.html` дотор өөрчлөлтгүй бий.

Production болон offline горим:

```bash
npm run build
npm start
```

PWA service worker нь production build-д ажиллана. Build команд JavaScript/CSS-ийн offline manifest болон service worker-ийг үүсгэдэг тул `npm run build` командыг ашиглаарай. Апп болон offline asset-ууд анх бүрэн татагдсаны дараа сүлжээгүй ашиглана. Суурин байршуулалт HTTPS байна; localhost хөгжүүлэлтэд зөвшөөрөгдөнө.

## Хийсэн боломжууд

- **Нүүр:** өнөөдрийн хугацаа, одоогийн дараалал, долоо хоногийн явц, нийт суралцсан өдөр, хичээлүүд, сүүлийн түүх.
- **Timer:** stopwatch; pause/resume; эхэлсэн мөч хадгалагдана; цонх сэргээхэд үргэлжилнэ; Finish → тэмдэглэлээ засах → Save result. Давхар хадгалалт хийхгүй.
- **Pomodoro:** 25/5, 50/10, 90/15 болон өөрийн хугацаа; төвлөрөл, богино/урт амралт. Амралтыг суралцсан хугацаанд тооцохгүй. Хожуу нээгдсэн цонх ч тогтоосон хугацаанаас хэтрүүлж тооцохгүй.
- **Календарь:** 30/90/365 өдрийн contribution grid; сарын харагдац; өдөр ба хичээлээр шүүх; гараар суралцсан өдрөө тэмдэглэх.
- **Хичээлүүд:** нэмэх, нэр/өнгө засах, архивлах, хогийн сав, сэргээх; хичээл тус бүрийн хугацаа, дундаж, 7/30 өдрийн график, календарь.
- **Статистик:** 7/30/90/365/бүх хугацаа; хичээлийн шүүлт; дундаж, тогтмол байдал, урт дараалал, хамгийн идэвхтэй өдөр/цаг, хугацааны хуваарилалт.
- **Долоо хоногийн тайлан:** хугацаа, зорилгын хувь, суралцсан өдөр, идэвхтэй хичээл/өдөр, өмнөх бүтэн долоо хоног; өсөлтийг ижил гарагуудаар харьцуулна.
- **Зорилго:** долоо хоногийн цаг/өдөр, нэмэлт өдрийн минут/сарын цаг. v2-ийн амжилтын ID, биелсэн огноог хадгалсан.
- **Өдрийн төлөвлөгөө:** өдөр, хичээл, хугацаа, эхлэх цаг, биелэлт; төлөвлөгөөнөөс timer эхлүүлж болно.
- **Суралцах туслах:** бодит түүхээс тооцсон дүгнэлт, өнөөдрийн төлөвлөгөөний санал. AI API холбогдоогүйг ил тод харуулна; API нэмэх provider interface бий.
- **Тохиргоо:** light/dark/system, timer, мэдэгдэл/дууны сонголт, JSON экспорт/импорт/нөөц/сэргээх, нэгтгэлийн зөрчил шийдэх.
- **Cloud холболт:** Supabase email/password, Google OAuth, нууц үг сэргээх, хэрэглэгч тус бүрийн локал кэш, зөвшөөрсөн guest merge, offline өөрчлөлтөө дахин sync хийх.

## Хуучин өгөгдлөө шилжүүлэх

**Өөр домэйн/порт/браузер руу шилжвэл:** v2-оос JSON нөөцөө татна. v3-ийн **Тохиргоо → JSON файл нэгтгэх** хэсэгт сонгоод, тоо болон зөрчлийн урьдчилсан харагдацыг шалгаж нэгтгэнэ. Браузер өөр origin-ийн хадгалалтыг уншдаггүй.

**Ижил origin дотор:** анхны нээлтээр `tracker-data`-г уншиж, яг эх JSON-ийг нөөцөлсний дараа шинэ IndexedDB санд шилжүүлнэ. Хуучин `tracker-data`-г өөрчлөхгүй. Байгаа `window.storage` холболт болон v2-ийн pending recovery journal-ийг танина.

Файл дахь ижил ID-тай хичээлийг давхар нэмэхгүй. Хоёр төхөөрөмж дээр өөрөөр зассан бичлэгийн хоёр хувилбарыг хадгалж, **Тохиргоо → Нэгтгэлийн зөрчил** хэсэгт сонгуулна. Бүтэц нь танигдаагүй мөрүүд JSON-ийн `quarantine` хэсэгт эхээрээ үлдэнэ. Нэг нэртэй хичээлийг нэгтгэхдээ хуучин ID, metadata-г архивласан alias мөрөөр хадгалдаг.

Дэлгэрэнгүй: [Шилжилт ба сэргээх](docs/MIGRATION.md).

## Supabase ба Vercel

Cloud хэрэглэх бол [Байршуулах заавар](docs/DEPLOYMENT.md)-ыг дагана. Зөвхөн public URL, **publishable key**-г браузерт оруулна. Secret/service-role key бүү ашиглаарай.

SQL migration: `supabase/migrations/20260915075237_study_os_v3.sql`. Энэ нь хэрэглэгчээр тусгаарласан RLS, composite foreign key, explicit authenticated grants, revision шалгадаг atomic RPC-уудтай. Хүснэгтүүдийн тайлбар: [Өгөгдлийн сан](database/README.md).

Эх код: [AriukagiinTuvshoo/TOGTMOL](https://github.com/AriukagiinTuvshoo/TOGTMOL). Одоогоор live Supabase төсөл болон байршуулсан URL тохируулаагүй.

## Шалгалт

```bash
npm run check
npm run format:check
```

`check` нь TypeScript, ESLint, Vitest тест, production build ажиллуулна. Тестүүд нь timer, v2 шилжилт, хамгаалалттай хадгалалт, статистик, хогийн сав/сэргээх, sync, жинхэнэ PostgreSQL engine дээрх RLS/transaction, React интерфэйсийн урсгал, service worker-ийн нөөцлөлтийг шалгана. 10,000 бичлэгийн хэмжилт `test-results/performance.json`-д бичигдэнэ.

Тестийн SQL нь тусгаарласан **PGlite** дотор ажилладаг. Live өгөгдлийн санд тестийн өгөгдөл бичихгүй.

Тайлан ба хязгаар: [Шалгалтын үр дүн](docs/VERIFICATION.md). Архитектур: [ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Хэрэглээний бодит хязгаар

- Браузерын өгөгдлийг цэвэрлэвэл локал түүх, нөөц арилна. JSON-оо татаж хадгалж байгаарай.
- Timer эхлүүлсэн төхөөрөмж дээрээ хадгалагдана; зэрэг төхөөрөмж дээр нэг timer үргэлжлүүлэхгүй.
- Сануулах цаг апп нээлттэй үед ажиллана. Апп хаалттай үеийн push серверийг энэ хувилбар тохируулаагүй.
- AI API болон төлбөртэй AI үйлчилгээ холбогдоогүй.
- Email, Google OAuth, хоёр бодит төхөөрөмжийн sync, iOS/Android install/offline, responsive харагдацыг live орчинд эцэслэн баталгаажуулах шаардлагатай. Автомат браузерын орчин localhost/file хандалтыг хориглосон тул харагдац шалгасан гэж тайлагнаагүй.
