## 5. Phase 1-ийн эхлэлийн баримт

- **Аудио Cloud Sync — migration орсон (2026-11-12).** `supabase/migrations/20260924201500_music_audio_sources_v6.sql` нэмэгдсэн: `youtube_id` nullable, `kind='audio'` зөвшөөрөгдөнө, `audioUrl` эсвэл `audioStorageKey`-ийн аль нэг нь заавал байна. Байхгүй тохиолдолд `coalesce(..., false)` ашигласан — эс бөгөөс SQL-ийн NULL нь CHECK-ийг "давсан" гэж үзэж, тоглуулах боломжгүй бичлэг хадгалагдах байсан. Схем 5 хэвээр. `tests/database.test.ts` дэх `v6 audio music sources` бүлэг (3 тест) бодит PGlite дээр батална: URL ба файлын аудио round-trip, `youtube_id` NULL/`''`, аудио тодорхойлогчгүй/буруу түлхүүр/буруу схем татгалзагдах, видео/playlist-ийн шалгалт хэвээр.
- **Аудио бодлого.** URL аудио бүх төхөөрөмжид синк хийгдэнэ; `audioStorageKey` файлын байт нь зөвхөн оруулсан төхөөрөмж дээр үлдэж, бусад төхөөрөмж дээр тодорхой мессеж гарна ([MUSIC.md](MUSIC.md)). Аль нэг аудио эх сурвалж нь өмнө нь бүхэл бүртгэлийн push-ийг унагадаг байсан — migration үүнийг зассан.
- **Хоёр төхөөрөмжийн синк — scenario тест (2026-11-12).** `tests/two-device-sync.test.ts` нь хоёр тусдаа IndexedDB төхөөрөмж, бодит `SyncEngine` ба `SupabaseAdapter`, бодит PGlite PostgreSQL (RLS, RPC, migration) дээр 6 scenario ажиллуулна:
  1. нэг бүртгэлийн А төхөөрөмжөөс В рүү хичээл, session, аудио эх сурвалж шилжих, буцаж В-ийн session А руу орох;
  2. хоёр төхөөрөмж нэг хичээлийг зэрэг засах үед хоёр хувилбар `conflicts`-д үлдэх, шинэ нь ялах, дараа нь хоёулаа ижил төлөвт нийлэх;
  3. push унах үед офлайн засвар локалд үлдэх, дараагийн синкэд байршиж нөгөө төхөөрөмжид хүрэх;
  4. үүлэн устгалтын дараа локал түүх зөвшөөрөлгүй буцаж байршихаас татгалзах, зөвшөөрлийн дараа `cloudResetAt` хадгалагдан байрших;
  5. эвдэрсэн бүртгэлийг яг байгаагаар нь нөөцөлж, ил сэргээх, сэргээх нь синкийг унтраадаг тул дахин холбож, давхардалгүй байршуулах;
  6. төхөөрөмжийн аудио файлын мета үүлээр дамжих боловч байт нь зөвхөн эх төхөөрөмж дээр байх.
     Scenario бүр цэвэр үүлэн сангаас эхэлнэ; нэг тестийн reset epoch нөгөөгийнхөд нөлөөлөхгүй.

Энэ ажлын орчинд `SUPABASE_PRODUCTION_URL`, `SUPABASE_PRODUCTION_PUBLISHABLE_KEY`, `SUPABASE_TEST_EMAIL`, `SUPABASE_TEST_PASSWORD`, `SUPABASE_EXPECTED_PROJECT_REF` байхгүй тул бодит үйлчилгээний тестийг ажиллуулж чадаагүй. Бэлэн хэрэгсэл: `npm run verify:supabase:production` ба `.github/workflows/supabase-production-smoke.yml`.

## 6. Phase 2 — PWA, гар утасны навигаци ба хүртээмж (эхэлсэн)

Дэлгэрэнгүй: [PWA.md](PWA.md).

- **Offline.** `/privacy`, `/terms` одоо service worker-ийн кэшэд орсон — өмнө нь offline үед эдгээр хуудас аппын нүүр рүү шилждэг байсан. API, auth, токентой болон гаднын хүсэлт кэшлэгдэхгүй хэвээр.

## 7. Phase 3 — FSRS (эхэлсэн)

Дэлгэрэнгүй: [FSRS.md](FSRS.md).

- **SM-2 анхдагч хэвээр.** FSRS нь Тохиргоо → «Давтлагын алгоритм»-аас сонгогдох ба ижил `ReviewSchedule` бүтцийг буцаадаг тул queue, түүх, синк, экспорт хөндөгдөөгүй.
- **FSRS-4.5 бөгөөд бүрэн.** `lib/knowledge/fsrs.ts`: нийтлэг 17 жин, мартах муруй, `D0/S0`, амжилт/алдааны тогтвортой байдал, коэффициент ба хязгаарууд. 0–2 → Again, 3 → Hard, 4 → Good, 5 → Easy буулгалттай.
- **Түүхээс сурах.** `lib/knowledge/calibrate.ts` нь давтлагын түүхээс нэг тогтвортой байдлын коэффициентийг log-loss-оор тааруулна; 40-өөс доош ажиглалт эсвэл ач холбогдолгүй сайжруулалтад анхдагчаа үлдээнэ. Зөвхөн хэрэглэгчийн товч дарахад хадгална.
- **Хадгалалт.** `ReviewSchedule`-д `algorithm/stability/difficulty/lastReview` нэмэгдэж, validation болон `migrate()` тэдгээрийг хадгална — үүлэн синк, JSON нөөцөд автоматаар орно.
- **Тест.** `tests/fsrs.test.ts` — 19 тест (муруй, үнэлгээ, тогтвортой байдал, калибровкын чиглэл ба босго, SM-2/FSRS интеграци, round-trip); `tests/fsrs-ui.test.tsx` — Тохиргооны сонголт SM-2-оос FSRS руу шилжиж, `aria-pressed` болон тайлбар шинэчлэгдэхийг шалгана.
- **Импорт ба экспорт.** `lib/knowledge/anki.ts` Anki-ийн текст/CSV/TSV-ийг уншиж (meta толгой, RFC 4180 ишлэл, HTML цэвэрлэлт, тусгаарлагч таних), Anki-д оруулах TSV ба хүснэгтийн CSV үүсгэнэ; давхардсан асуултыг сонгосон багцад алгасна. `.apkg` нь SQLite/zstd архив тул шууд уншигдахгүй — шалтгааныг UI тайлбарлана.
- **Импортын дараах давтлага.** `knowledgeIndex` нь өдрийн шинэ картын хязгаарыг (`extras.newCardsPerDay`, анхдагч 20, 0 = хязгааргүй) харж, тухайн өдөр аль хэдийн нээсэн шинэ картыг хасна; шинэ картууд `dueOn → createdAt → id` дарааллаар гарна. Ингэснээр 500 картын импорт нэг өдөр дараалалыг дүүргэхгүй, хугацаа болсон карт харин үргэлж бүгд гарна. Мэдлэгийн сан, самбар, сануулга, зөвлөх нэг ижил хязгаарыг харна.
- **Давтлагын цонх.** Нэг давтлагын дээд хэмжээ `extras.reviewSessionLimit` (анхдагч 200, 0 = хязгааргүй, 2000 хүртэл) болж тохируулагдав; цонхон дотор багцаар шүүх (`Бүх багц` эсвэл тухайн багц — шүүлт хязгаараас өмнө) ба 10/20/30/45 минутын хугацааны хязгаар нэмэгдэв. Цаг дуусахад карт албадан хаагдахгүй — «10 минут нэмэх» эсвэл «Дуусгах» сонголт гарна. Туслах функцууд `lib/knowledge/session.ts`.
- **PDF ба файл.** `lib/knowledge/pdf.ts` Flate/шахалтгүй stream, `Tj/TJ` оператор, escape, `ToUnicode` CMap (кирилл) уншина; карт ба quiz үүсгэгчид PDF/TXT/MD файлаас материал ачаална. Скан хийсэн PDF, object stream дэмжигдэхгүй.
- **Үлдсэн.** Бүрэн жин сургах (сервер талын оптимизатор), FSRS-5/6-ийн нэг өдрийн доторх загвар, `.apkg` ба Anki media, PDF-ийн layout сэргээлт.
