# Хувилбарын дугаарлалт

> Энэ апп дөрвөн өөр «хувилбар»-ыг зэрэг ашигладаг тул тэднийг ялгахгүй бол баримт бичиг зөрчилддөг. Доорх хүснэгт нь бодит кодоос авсан нэг эх сурвалж юм.

## 1. Одоогийн дугаарууд

| Юу                            | Утга               | Хаана тодорхойлогдоно                                     |
| ----------------------------- | ------------------ | --------------------------------------------------------- |
| Аппын хувилбар                | `7.0.0`            | `package.json` → `version`                                |
| Хадгалалтын схем              | `6`                | `lib/persistence/repository.ts:158`, `data.schemaVersion` |
| IndexedDB-ийн нэр             | `togtmol-v3`       | `lib/persistence/repository.ts:27`, `store.ts:70`         |
| IndexedDB-ийн дотоод хувилбар | `3`                | `repository.ts` дахь `open(DB_NAME, 3)`                   |
| localStorage prefix           | `togtmol:v3:`      | `lib/persistence/repository.ts`                           |
| JSON экспортын `version`      | `6`                | `lib/persistence/store.ts:230`                            |
| Supabase migration файлууд    | `v3`–`v7` (5 файл) | `supabase/migrations/` (таван файл)                       |
| Supabase дээрх схем           | `6`                | RPC болон `schemaVersion` шалгалт                         |

**Чухал:** migration файлын нэрний дугаар нь **схемийн** дугаар биш, зүгээр л файлын дараалал юм. `20260924201500_music_audio_sources_v6.sql` нь дөрөв дэх файл бөгөөд схем 5 дээр ажиллана. Тав дахь файл `20261114120000_topics_knowledge_v7.sql` нь схем 6-ыг нэвтрүүлнэ: `topic` төрөл, `topicId`, багцын `sourceId`. Одоо зөвхөн схем 6 upload хүлээж авах ба schema 5 ба түүнээс хуучин upload татгалзагдана.

## 2. Аль дугаарыг хэзээ өсгөх вэ?

### Аппын хувилбар (`package.json`)

- **Major** — хэрэглэгчийн өгөгдөл, экспортын формат эсвэл API-ийн нийцтэй байдал эвдэх үед.
- **Minor** — шинэ боломж, шинэ дэлгэц, шинэ тохиргоо нэмэхэд.
- **Patch** — алдаа засах, гүйцэтгэл, хүртээмж, баримтын засварт.

Аппын хувилбар нь өгөгдлийн схемээс **хөндий** хөгжинө: 7.x бүхэлдээ схем 6 дээр ажиллаж болно.

### Хадгалалтын схем (`schemaVersion`)

Схем өсгөх нь зөвхөн хадгалагдсан өгөгдлийн хэлбэр өөрчлөгдөх үед — талбар нэмэх/устгах, утгын утга өөрчлөх, шинэ цуглуулга нэмэх. Нэг дор дараах бүх зүйл хийгдэнэ:

1. `types/` дахь төрлүүд шинэчлэгдэнэ.
2. `lib/persistence/repository.ts` дахь `migrate()` болон `schemaVersion` шалгалт шинэ дугаар руу шилжинэ.
3. `store.ts` дахь экспортын `version` мөн өснө (одоо 5).
4. `docs/MIGRATION.md`-д шилжилтийн дүрэм, эрсдэл, буцаах зам бичигдэнэ.
5. `tests/database.test.ts`, `tests/sync.test.ts`, `tests/recovery-v5.test.ts` шинэ схем дээр ажиллана.
6. Хуучин схемээс ирсэн өгөгдөл нээгдэхээс өмнө бүтэн эх envelope нөөцлөгдөнө.

Схем 3 эсвэл 4-өөс ирсэн үүлэн upload татгалзагдана — хуучин үйлчлүүлэгч шинэ өгөгдлийг дарж бичихээс сэргийлнэ.

### Supabase migration

- Файлын нэр: `YYYYMMDDHHMMSS_<тайлбар>_v<N>.sql`.
- Файл нь **зөвхөн нэмэгдэнэ**. `main` дээр орсон migration-ыг засахгүй, шинэ файл нэмнэ.
- Дарааллыг нэрээр тодорхойлно; production дээр аль хэдийн ажилласан файлыг дахин нэрлэхгүй.
- SQL нь RLS болон RPC-ийн эрхийг шалгана; `tests/database.test.ts` PGlite дээр бодитоор ажиллуулна.
- Аль нэг файл дутуу байвал түүнээс хамаарах функц (жишээ нь v6-гүй бол аудио эх сурвалжтай синк) бүхэлдээ татгалзагдана.

### IndexedDB-ийн нэр ба prefix

`togtmol-v3` нэр болон `togtmol:v3:` prefix нь **түүхэн** — v7 дээр ч өөрчлөгдөөгүй. Эдгээрийг өөрчлөх нь хэрэглэгчийн бүх локал өгөгдлийг «алга болгосон» мэт харагдуулна. Дотоод бүтэц өөрчлөгдөхөд `indexedDB.open`-ийн дотоод хувилбарыг л өсгөнө (одоо 3: `documents`, `backups`, `metadata`, `knowledge`, `musicBlobs`).

## 3. Хувилбар гаргахын өмнө

```bash
npm ci
npm run check          # typecheck → lint → format → test → build
npm run verify:supabase:production   # production түлхүүртэй орчинд
```

Дараа нь:

1. `CHANGELOG.md`-ийн `[Unreleased]` хэсгийг тухайн дугаар руу шилжүүлж, огноог бичнэ.
2. Өөрчлөгдсөн дугаарыг `package.json`, `README.md`, `docs/ARCHITECTURE.md`, `docs/DEPLOYMENT.md` дөрөвт нь тааруулна.
3. Баримт дахь тоо (тест, файл, migration) нь хэмжсэн үр дүнтэй таарч байгааг `docs/VERIFICATION.md`-ээр батална.

## 4. Хөндөхгүй үлдээсэн нэрс

- `TOGI_AI_ALLOWED_USER_IDS`, `CHIMEGE_API_TOKEN` зэрэг орчны хувьсагчдын нэр — production дээр аль хэдийн тохируулагдсан тул нэрлэхдээ л шинэ нэрийг (жишээ нь `BONDOOK_AI_ALLOWED_USER_IDS`) эхэнд тавьж, хуучин нэрийг fallback болгон үлдээнэ.
- `/api/togi` route-ийн зам — клиент болон гадны дуудлага эвдэхгүйн тулд хэвээр.
