# Тогтмол v4.1 — шалгалтын тайлан

Огноо: 2026-09-16. Орчин: Linux, Node.js v24.19.0, Next.js 16.3.5, TypeScript 6.0.3. Энэ тайлан эх кодын локал шалгалтыг тайлбарлана.

| Шалгалт                                       | Үр дүн                                                   |
| --------------------------------------------- | -------------------------------------------------------- |
| Хамаарлууд                                    | v4-ийн суулгалтыг ашигласан; хамаарлын хувилбар солиогүй |
| TypeScript                                    | Алдаагүй                                                 |
| ESLint                                        | Алдаа, анхааруулгагүй                                    |
| Vitest                                        | **110 / 110** тест, **13 / 13** файл                     |
| `npm run check`                               | Бүх шат тэнцсэн, production build багтсан                |

## Юуг бодитоор шалгасан бэ?

- **Хугацаа:** эхэлсэн мөч, pause/resume, сэргээх, Pomodoro-ийн хэтрэлтийн хязгаар, амралт, review/save, давхар хадгалалтгүй байх, экспортын snapshot.
- **v2/v3 → v4:** ID, түүх, тэмдэглэл, нэмэлт талбар болон ажиллаж буй timer хадгалагдах; эх хадгалалтыг нөөцөлсний дараа бичих; нөөц бүтэлгүйтвэл бичихгүй байх; давтан шилжүүлэлтгүй байх.
- **Хадгалалт ба sync:** зэрэг цонхны revision, хэрэглэгчдийн тусгаарлалт, гурван хувилбарын merge, tombstone, давхар хичээлийн alias, шинэ зорилго/хөгжмийн жагсаалт, хоёр хувилбарын зөрчлийг хадгалах.
- **Өрөө ба төлөвлөгөө:** загвар/өрөөний сонголт дахин нээхэд хадгалагдах; хуваарийг хадгалахаас өмнө урьдчилж харах; зорилгын алхмаас төвлөрөх горимд timer эхлүүлэх; Escape дарахад хугацаа алдагдахгүй байх; үр дүн болон тэмдэглэлээ хадгалах.
- **Үе шат ба засвар:** үе шатуудад даалгавар хуваарилах, тайлбар/өдрийн тоо хадгалах, зорилго засахад түүх өөрчлөхгүй байх, идэвхтэй даалгаврыг засахаас хамгаалах, шинэчилсэн хувилбарын зөрчил шалгах. Үе шат сольсон ч өмнөх хэмжилтийн холбоос хэвээр; эхлэхдээ үе шатгүй байсан хэмжилтийг дараа нь автоматаар холбохгүй.
- **Бодит ахиц:** төлөвлөгөө чагтлахад минут, XP нэмэхгүй; зөвхөн холбогдсон хичээлийн хугацаагаар зорилгын ахиц тооцох; XP өдөрт 60-аас хэтрэхгүй; гараар зассан хугацаа, өдрийн чагтыг XP-д оруулахгүй.
- **Календарь ба статистик:** шөнө/долоо хоног дамнасан хэмжилтийг бодит өдрүүдэд хуваарилах, зөвхөн тухайн зорилгын долоо хоногийн минутыг тооцох; биелсэн өдрийг хуваарь зассанаас үл хамааран хадгалах; 20/40/60 минутын шатлал, хэмжээгүй өдрийн тэмдэглэл, дараалал ба хамгийн урт хэмжилт.
- **Хөгжим:** долоон ая/чимээ тус бүр хязгаартай, бодит тоон дууны sample үүсгэх; эхлүүлэх/түр зогсоох/үргэлжлүүлэх/цэвэрлэх; апп нээхэд өөрөө асахгүй; хуудас солиход тоглуулагч хадгалагдах; үндсэн ангилал, дууны түвшин, сүүлд тоглуулсан сонголтыг тохиргоо ба тоглуулагч хамт ашиглах.
- **YouTube:** зөвшөөрөгдсөн host ба ID шалгах; буруу холбоосоор iframe ачаалахгүй; албан ёсны API-д `autoplay:0`, controls, playsinline дамжуулах; тоглуулагчийг багасгахын өмнө pause хийх. API болон аудио төхөөрөмжийг эдгээр тестэд орлуулсан.
- **Тоги:** local хариулт бодит статистик, тэмдэглэлээс гарах; хуваарийн санал нь сонгосон суралцах өдрүүдэд тулгуурлах, хуучин зорилгын өдрийн тоог зохиохгүй байх; долоо хоногийн хичээл тус бүрийн хугацаа; онлайн хүсэлтэд тэмдэглэл анхдагчаар оруулахгүй, тусдаа зөвшөөрөлтэй үед хязгаартай хэсэг оруулах; UTF-8 хүсэлтийн хэмжээ хязгаарт багтах; онлайн алдаанд Local гэж тэмдэглэсэн хариулт өгөх. API түлхүүргүй үед paid provider дуудахгүй; нэвтрэлт/серверийн allowlist/өдрийн хязгаар; том хүсэлтээс татгалзах; зөвхөн хариултын текст буцаах, upstream алдаа/түлхүүр задруулахгүй байх.
- **Нөөц ба цэвэрлэх:** хуучин дотоод нөөцийн `{revision,data}` хэлбэрийг сэргээх; төхөөрөмжийн түүхийг эхлээд нөөцөлж цэвэрлэх, сэргээх боломжтой байх; нэвтэрсэн хэрэглэгчийн өгөгдөл хөндөхгүй байх. Нөөц бүтэлгүйтэх, өөр цонх бичих, таймер ажиллах үед цэвэрлэхгүй.
- **PostgreSQL:** PGlite бодит SQL engine дээр хоёр migration, есөн public хүснэгтийн RLS, хэрэглэгч хоорондын хамгаалалт, atomic RPC, CAS, rollback, foreign key, шинэ зорилго/хөгжмийн round trip, хуучин v3 upload-аас татгалзах, private AI quota-г хэрэглэгч өөрчлөх боломжгүй байх.
- **PWA:** offline asset нөөцлөлт, auth/Supabase/API болон гаднын request-ийг cache-д оруулахгүй байх, хуучин cache цэвэрлэх, шинэ хувилбар хуучин цонхыг хүчээр дахин ачаалахгүй байх.

React тестүүд **jsdom** дээр ажилласан. Хөгжмийн тест дууны өгөгдөл болон удирдлагын дарааллыг шалгасан; чанга яригчаар сонсож баталгаажуулаагүй. YouTube API-г орлуулсан тест нь жинхэнэ YouTube сүлжээ/playback-ийн баталгаа биш. AI тестүүд хиймэл түлхүүр, орлуулсан provider ашигласан; төлбөртэй хүсэлт илгээгээгүй.

## Зургийн шалгалт ба үлдсэн ажил

v4 дээр өрөөний таван оригинал SVG зургийг тусад нь PNG болгож нүдээр шалгасан. `docs/previews` нь тэр хувилбарын зурган assets; бүрэн браузерын screenshot биш. v4.1-ийн шинэ тавилгын сонголтуудыг бодит браузерт хараахан нүдээр шалгаагүй.

Браузерын орчин localhost хандалтад `ERR_BLOCKED_BY_CLIENT` өгсөн. Тиймээс 320/375/390/430/768/1024/1440 өргөн дэх бодит дүрслэл, браузерын console, YouTube playback, iOS/Android install болон төхөөрөмж дээрх offline ажиллагааг тэнцсэн гэж тайлагнаагүй. CSS, accessible label, keyboard/диалог, хөдөлгөөн багасгах тохиргоо болон тестээр шалгаж болох урсгалуудыг хийсэн. PWA бэлэн эсэх болон хүлээгдэж буй шинэчлэлтийг интерфейст харуулдаг; энэ нь төхөөрөмж дээрх install/offline шалгалтыг орлохгүй.

Бодит Supabase төсөл, AI түлхүүр, Google provider, live URL тохируулаагүй. Email confirmation, Google callback, password recovery, хоёр бодит төхөөрөмжийн sync болон онлайн AI-г байршуулсан орчинд шалгах шаардлагатай. Заавар: [DEPLOYMENT.md](DEPLOYMENT.md).

GitHub-ийн тусдаа шалгалтыг [Actions](https://github.com/AriukagiinTuvshoo/TOGTMOL/actions) хэсгээс харна.
