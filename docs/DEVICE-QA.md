# Phase 3 — Бодит төхөөрөмжийн QA

> Энэ шалгалтыг **автомат тест халхлахгүй**. `npm run check` нь 318 тестээр offline кэш, update flow, timer тооцоолол, audio төлөвийг jsdom дээр баталдаг ч жинхэнэ OS-ийн background, түгжээтэй дэлгэц, autoplay бодлого, Wake Lock, Media Session-ийг батлахгүй. Доорх алхмуудыг төхөөрөмж бүр дээр гараар хийнэ.

## 0. Бэлтгэл

| Зүйл    | Утга                                                                                                                               |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Build   | `main` дээрх хамгийн сүүлийн ногоон commit; footer дээр `TOGTMOL v7`, `public/precache-manifest.json` дахь `build` id-г тэмдэглэнэ |
| URL     | Production HTTPS хаяг (PWA суулгах, notification ажиллахад HTTPS заавал)                                                           |
| Бүртгэл | 2 хэрэглэгч (A, B) — cross-device синк шалгахад                                                                                    |
| Өгөгдөл | 1 хичээл, 3 карттай багц, 1 YouTube холбоос, 1 `audioUrl` холбоос, 1 төхөөрөмжийн аудио файл                                       |

Төхөөрөмжийн матриц:

| #   | Төхөөрөмж        | Хөтөч                           | Тэмдэглэл                                     |
| --- | ---------------- | ------------------------------- | --------------------------------------------- |
| D1  | iPhone (iOS 17+) | Safari → **Add to Home Screen** | Notification зөвхөн суулгасан PWA дээр        |
| D2  | Android (13+)    | Chrome → **Install app**        | Wake Lock, Media Session бүрэн                |
| D3  | Windows 11       | Edge (эсвэл Chrome)             | Desktop; Lighthouse/Media Session харьцуулалт |

## 1. Offline (D1, D2, D3)

1. Онлайнаар нээж, 5 бүлгийн бүх дэд дэлгэцийг нэг удаа нээгээрэй (кэш дүүрэхэд).
2. Онгоцны горимд оруулна.
3. Аппыг бүрэн хааж дахин нээнэ.

| #   | Алхам                                     | Хүлээгдэх үр дүн                                                                                 |
| --- | ----------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 1.1 | Апп ачаалах                               | Үндсэн дэлгэц рендэрлэгдэнэ, «Офлайн» төлөв харагдана                                            |
| 1.2 | `/privacy`, `/terms` нээх                 | **Тухайн хуудасны агуулга** гарна — нүүр хуудас руу шилжихгүй (энэ нь service worker-ийн засвар) |
| 1.3 | Баталгаажаагүй гүн холбоос (`/#/unknown`) | Кэшлэгдсэн shell гарна, хоосон дэлгэц эсвэл crash биш                                            |
| 1.4 | Хичээл/тэмдэглэл үүсгэх, хадгалах         | Локал IndexedDB-д хадгалагдана, reload-ийн дараа хэвээр                                          |
| 1.5 | Онлайн AI, YouTube, синк                  | Тодорхой мессеж («интернет хэрэгтэй»), чимээгүй унахгүй                                          |
| 1.6 | Дараа нь онлайнд буцах                    | Синк/сэргээх ажиллаж, давхардал үүсэхгүй                                                         |

**Мэдэгдэж буй хязгаар:** эхний ачаалалт интернет шаардана; `/api/*` кэшлэгдэхгүй; YouTube ба AI офлайн ажиллахгүй.

## 2. Service worker update (D1, D2, D3)

1. Хуучин build-ыг нээлттэй үлдээнэ.
2. Шинэ build байршуулна (кодын өөрчлөлт нь харагдахуйц байвал сайн — жишээ нь footer/текст).
3. Табыг буцааж идэвхжүүлнэ (эсвэл 1 минут хүлээнэ; шалгалт минутад хамгийн ихдээ нэг удаа).

| #   | Алхам              | Хүлээгдэх үр дүн                                                                          |
| --- | ------------------ | ----------------------------------------------------------------------------------------- |
| 2.1 | Идэвхжүүлэх        | «Шинэ хувилбар бэлэн» мэдэгдэл гарна                                                      |
| 2.2 | «Одоо шинэчлэх»    | Хуудас дахин ачаалагдаж, шинэ `build` id харагдана                                        |
| 2.3 | «Дараа» (× товч)   | Мэдэгдэл хаагдана, хуучин хувилбар ажиллана; дараагийн идэвхжүүлэлтэд дахин санал болгоно |
| 2.4 | Алдааны зам        | 5 секундэд шилжихгүй бол «Шинэчлэлтийг идэвхжүүлж чадсангүй…» мессеж + цонх хаах заавар   |
| 2.5 | Шинэчлэлтийн дараа | Өгөгдөл (хичээл, карт, тохиргоо) хэвээр; давхар session үүсэхгүй                          |

**iOS:** Safari нь background таб дээр SW-г шалгахгүй — аппыг бүрэн хааж (App Switcher-ээс) дахин нээх шаардлагатай. Үүнийг алдаа биш, платформын хязгаар гэж тэмдэглэнэ.

## 3. Timer background (D1, D2, D3)

Урьдчилсан: Тохиргоо → «Timer ажиллаж байх үед дэлгэцийг сэрүүн байлгах» асаалттай, мэдэгдэл зөвшөөрөгдсөн, дуу асаалттай.

1. 25 минутын timer эхлүүлж, дэлгэцийг түгжинэ (D3 дээр табыг minimize).
2. 5+ минут хүлээгээд буцаж нээнэ.

| #   | Алхам                   | Хүлээгдэх үр дүн                                                                |
| --- | ----------------------- | ------------------------------------------------------------------------------- |
| 3.1 | Буцаж нээх              | Өнгөрсөн хугацаа **хадгалсан timestamp-аас** тооцогдоно (зогссон биш)           |
| 3.2 | Timer дуусах            | «⏰ Хугацаа дууслаа!» мэдэгдэл/гарчиг, дуу; D2/D3 дээр OS-ийн мэдэгдэл          |
| 3.3 | Аппыг албадан хааж нээх | Идэвхтэй timer сэргээгдэж, үргэлжилнэ                                           |
| 3.4 | Дэлгэц сэрүүн           | D2/D3 дээр ажиллана (Wake Lock API); **iOS Safari-д дэмжигдэхгүй** — тэмдэглэнэ |
| 3.5 | Давхар бичлэг           | Нэг session л хадгалагдана, дуусах үед давхар alert гарахгүй                    |

**Мэдэгдэж буй хязгаар:** iOS Safari background-д JS-ийг түр зогсоодог тул alert хожимдож болно; notification нь зөвхөн Home Screen-д нэмсэн PWA дээр ажиллана. `docs/PWA.md` §5-д энэ нь баталгаа биш гэж бичигдсэн.

## 7. Phase 3-ын гарах шартууд

- 1.1–1.4, 2.1–2.2, 3.1–3.3, 4.1–4.3 бүх гурван төхөөрөмж дээр **PASS**.
- Ямар ч шалгалтад өгөгдөл алдагдахгүй, crash гарахгүй.
- Давхар session, давхар notification, хуурамч «тоглож байна» төлөв илрээгүй.
- Платформын хязгаарууд (iOS Wake Lock, iOS background alert, iOS SW update) энэ баримтад тэмдэглэгдсэн — «алдаа» гэж нээлттэй үлдээхгүй.

Энэ баримтыг шинэчлэхдээ төхөөрөмж, OS, хөтчийн хувилбар, build id-г хамт бичнэ.
